# T1 결과: 정상 흐름 대조 실행의 배치 (시뮬레이션, 2026-11-16)

계획: docs/round8_plan.md T1. 예측("시간 정렬 < 순차 ≤ 없음, 확신 오류 기준")은 커밋 bab0c92에서 실행 전에 적었다. 판정 엔진은 v2.2 그대로이다.

## 설정
- **장애:** 시행마다 절대 시각 축의 "거부 창"(포아송, 길이 D ∈ {10, 60, 180}초, 다운 비율 f ∈ {5%, 10%}). 창 안의 인증 요청은 서버에 닿지 않고 거부된다(앞단 WAF·속도 제한기 모사).
- **조건:** T3 시뮬레이션과 같은 5개 모델 조건. 대상 2(BE·BS형, 카운터형), 비대상 3(정상, 일시 잠금, 단일 무효 서명 폐기).
- **반복:** 조건마다 300시행. 각 프로브는 [0, 3600)초에서 무작위로 시작한다.
- **비교할 배치:** 순차(현재 수집 방식), 시간 정렬(대조 정상 단계를 프로브의 같은 단계 0.5초 전에), 없음.

**시간 정렬의 놓침 확인(f=10%, D=10).** 대상 두 조건에서 놓침 9건(4 + 5)은 **모두 거부 창이 결함 프로브의 공격 요청 자체를 막아 오염이 생기지 않은 시행**이었다. 시행 기준으로는 차단 없음이 사실이다. 따라서 시간 정렬 배치의 실제 놓침은 0이다.

## 해석
1. **대조 실행의 기여가 나타났다.** 시간적으로 몰리는 거부 창에서 대조 실행을 빼면 FAILSAFE 오탐이 최대 27건(f=10%, D=180), 규칙 판정의 확신 놓침이 최대 63건 생겼다. 현재 순차 배치는 이를 각각 0~3건과 0~4건으로 줄였다.
   - 4.6절 구성요소 제거에서 기여가 보이지 않은 것은 대칭·독립 잡음이 대조 기호까지 뒤집어 유보만 늘렸기 때문이다. 시간 상관 장애라는 대조 실행 본래의 목적에 맞는 조건에서는 기여가 분명하다.
2. **시간 정렬 대조는 남은 오탐을 모두 없앴다(0건).** 동시에 순차보다 유보도 적었다(예: 5%·D=10에서 319 → 227).
3. **사전 예측 중 "시간 정렬 < 순차(확신 오류 합계)"는 조건 단위 지표로는 틀렸다.** 원인은 공격 요청 자체가 막힌 시행이다. 시행 단위로 보면 성립한다. 예측이 틀린 사실과 그 이유를 함께 보고한다.
4. **실서버 실험은 하지 않는다.** 이 장애는 요청이 서버에 닿기 전에 일어난다. 실서버로 해도 클라이언트 쪽에서 같은 창을 주입하는 것과 같아 추가 정보가 없다. 대상 RP의 동작은 실서버 관측과 일치하도록 만든 모델 조건을 썼다.
5. **수집 프로토콜 개선안:** 시간 정렬 대조를 기본 배치로 바꾸면 거부형 장애에서 오탐 위험이 없어진다. 기존 결과는 순차 배치로 수집했으므로 논문에는 향후 개선으로 적는다.
